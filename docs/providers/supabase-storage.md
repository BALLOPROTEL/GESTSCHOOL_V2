# Supabase Storage Provider

Supabase Storage is the only durable storage provider supported in production.
The API uploads, reads and deletes objects with the service-role credential. The
browser never receives that credential or a storage object key chosen by the
client.

## Render configuration

`STORAGE_PROVIDER` is the canonical provider selector. `FILE_STORAGE_DRIVER` is
retained temporarily for backward compatibility with existing deployments; in
production both variables are required and must resolve to Supabase. They must
never be configured with different providers.

- `STORAGE_PROVIDER=supabase`
- `FILE_STORAGE_DRIVER=SUPABASE`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_STORAGE_BUCKET_DOCUMENTS=gestschool-documents`
- `SUPABASE_STORAGE_BUCKET_AVATARS=gestschool-avatars`
- `SUPABASE_STORAGE_AVATARS_PUBLIC=false`
- `SUPABASE_STORAGE_SIGNED_URL_TTL_SECONDS=300`
- `SUPABASE_STORAGE_TIMEOUT_MS=10000`

Never configure `SUPABASE_SERVICE_ROLE_KEY` in Vercel.

## Buckets and exposure

- `gestschool-documents` must be private. Teacher documents and attendance
  attachments are downloaded only through authenticated API routes with tenant,
  resource and permission checks.
- `gestschool-avatars` must also be private. The authenticated profile endpoint
  returns a short-lived signed URL generated by the API. The default lifetime is
  300 seconds and production validation restricts it to 60-900 seconds.
- Supabase object keys and the service-role credential remain server-side. A
  signed URL grants temporary access to one object; it must never be persisted as
  the canonical avatar URL.
- Receipts, invoices, report cards and analytics reports are not persisted in
  Supabase by the current application. Do not create or advertise storage
  buckets for them as if they were operational.

## Object paths

- avatars: `tenants/{tenantId}/avatars/{userId}/{randomUuid}.{extension}`
- teacher documents:
  `tenants/{tenantId}/teachers/{teacherId}/documents/{randomUuid}.{extension}`
- attendance attachments:
  `tenants/{tenantId}/attendance/{attendanceId}/attachments/{randomUuid}.{extension}`

The API validates every path segment and verifies the tenant prefix before read
or delete operations.

## Upload and download contract

The former generic `POST /api/v1/storage/upload-descriptor` endpoint has been
removed. Files are sent as multipart data to their business resource endpoint:

- `POST /api/v1/users/me/avatar`
- `POST /api/v1/teachers/{teacherId}/documents`
- `POST /api/v1/attendance/{attendanceId}/attachments`

Private downloads use:

- `GET /api/v1/teachers/documents/{documentId}/content`
- `GET /api/v1/attendance/{attendanceId}/attachments/{attachmentId}/content`

Avatar reads use the authenticated profile route. The returned `avatarUrl` is a
short-lived signed URL and may change between requests.

The API validates declared MIME, extension, binary signature and format parsing
before storage. Images are decoded; PDFs and Office archives are parsed with
bounded complexity checks.

## Unsupported drivers

`S3` and `WEBHOOK` are not implemented storage drivers. Selecting either causes
startup to fail explicitly. `LOCAL` is allowed only for development and tests;
it is always refused in production.

## Monitoring and smoke test

```bash
curl -H "x-metrics-token: $MONITORING_METRICS_TOKEN" \
  https://gestschool-ylik.onrender.com/api/v1/monitoring/providers
```

Then perform one real avatar upload and one private document upload/download as
an authorized account. Confirm that an unauthorized role and another tenant
receive a denial and that no service-role credential appears in responses or
logs.

## Incident handling

When Supabase is unavailable, uploads and protected downloads fail closed. Do
not switch production to local disk. Restore the provider, verify both buckets,
then repeat the smoke tests. Existing object keys must not be changed manually.
